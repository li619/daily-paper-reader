## 摘要
自动手写文本识别（HTR）本质上是一项具有挑战性的任务，而在处理连写文字时其复杂性进一步增加。尽管在各种连写文字上已开展了大量研究，但关于乌尔都语手写文本识别（UHTR）的研究相对有限。这一研究滞后主要归因于其文字系统带来的独特挑战，以及基准数据集的稀缺与不可获取。因此，为推动UHTR研究，本研究提出了一个专门的真实数据集，称为乌尔都语Katib手写数据集（UKHD）。据我们所知，这是首个专门从历史时期Katib书写材料中整理的离线乌尔都语手写文本行数据集。它涵盖了Nastalique书法风格中多样化的平头笔书写变体。此外，我们评估了不同基于CRNN的混合模型的有效性，以确定乌尔都语Katib手写识别（UKHR）的最优架构。在分析的模型中，CNN-BGRU-CTC模型表现出更稳健的性能，具有较低的字符错误率（CER）和词错误率（WER）。本研究工作旨在支持和鼓励研究社区开发稳健的识别系统，以保存乌尔都语手写文献。

## Abstract
Automatic Handwritten Text Recognition (HTR) is inherently a challenging task, and its complexity is further increased when dealing with cursive scripts. Although significant efforts have been made on various cursive scripts, research regarding Urdu Handwritten Text Recognition (UHTR) has been relatively limited. This lag of research is primarily due to the unique challenges posed by its script, and the scarcity and unavailability of benchmark datasets. Therefore, to advance research in UHTR, this study presents a specialized real dataset called the Urdu Katib Handwritten Dataset (UKHD). To the best of our knowledge, this is the first offline Urdu handwritten text lines dataset specifically curated from the materials written by Katibs in historical times. It encompasses a diverse range of flat nib writing variations in the Nastalique calligraphic style. Additionally, the effectiveness of different CRNN-based hybrid models has been evaluated to identify the optimal architecture for Urdu Katib Handwriting Recognition (UKHR). Among the analyzed models, the CNN-BGRU-CTC model showed more robust performance, with low Character Error Rate (CER) and Word Error Rate (WER). This research work aims to support and encourage the research community in developing a robust recognition system for preserving Urdu handwritten literature.

## 2. 方法论

### 2.1 数据集构建（UKHD）

- **数据来源**：从 Iqbal Academy Pakistan 官方数字库 Iqbal Cyber Library 下载 6 本 Katib 书写的乌尔都语书籍 PDF（1883–1977 年），转为页面图像。
- **规模**：共 13,213 条文本行，分两个子集——纯乌尔都语 PUTL（11,742 行）与混合语言 MUTL（1,471 行，含乌尔都语、英语、阿拉伯语、波斯语）；为现有离线乌尔都语手写文本行数据集中规模最大（对比 UNHD 10,000、NUST-UHWR 10,608 等）。
- **四阶段流程**：
  1. **图像采集**：PDF 转页面图像，按正确页码重命名。
  2. **预处理**：灰度化（OpenCV）→ 中值滤波去噪（窗口 3/5/7 按书籍噪声程度调整）→ 基于水平投影轮廓（HPP）的倾斜校正。倾斜校正算法：对 Sobel 边缘检测+反色后的图像在 [-5, 5) 度内逐角度旋转，计算各旋转图像的 HPP 中位数，取中位数最大（水平对齐最一致）的角度作为最优旋转角。
  3. **行分割（半自动）**：Otsu 二值化（白字黑底）→ 计算 HPP → 以阈值 60 估计行边界候选区域 → 剔除高度 ≤10 行的候选区（多由变音符号引起，防过分割）→ 取各区域中位数作为分割点裁剪文本行 → 在自研桌面应用中人工微调（上下平移、上下裁剪、跳过无效行）。图像 ID 格式为 `bbb-pppp-ll`（书 ID-页 ID-行 ID）。
  4. **标注（半自动）**：先用 Google Cloud Vision API 自动转写，再由人工专家逐条校对纠错，结果存入 PUTL/MUTL 两个 CSV 真值文件。

### 2.2 识别模型（CRNN 混合架构）

- **总体结构**：CNN（特征提取）+ RNN（序列建模）+ CTC（转录层），端到端训练。
- **CNN 部分**：7 个 Conv2D、4 个 MaxPool2D、4 个 Dropout（0.3）、2 个 BatchNorm；输入 32×384×1 灰度图，逐层下采样后经 Lambda 层 squeeze，得到 **95×512 的特征序列**（95 个时间步，每步 512 维特征向量）。
- **RNN 部分**：3 层双向 GRU（每层 512 隐藏单元，层间 Dropout 0.3），输出 95×74 的逐帧标签分布（73 类字符/符号 + 1 个 CTC blank）。
- **CTC 部分**：训练时对所有可能对齐求概率和以计算损失；测试时取每步最大概率路径，合并重复字符并删除 blank 得到最终文本。
- **对比的四种混合模型**：CNN-LSTM-CTC、CNN-GRU-CTC、CNN-BLSTM-CTC、CNN-BGRU-CTC（仅 RNN 组件不同）。
- **数据准备**：图像水平翻转（将 RTL 文字转为模型习惯的 LTR 顺序）、缩放至 32×384（保持纵横比+填充）、像素归一化至 [0,1]；标签做字符到 1–73 的数字编码，并填充至最大长度 90（填充值 73）。

### 2.3 训练策略与评价指标

- **超参数搜索**：学习率 {0.001, 0.0001, 0.0002, 0.0003, 0.0004}；优化器 {Adam, Nadam, RMSprop, Adamax}；批大小 {32, 64, 128}。
- **防过拟合**：Dropout(0.3)、BatchNorm、指数衰减学习率调度、早停（patience=33）。
- **指标**：CER 与 WER，基于 Levenshtein 编辑距离，公式为 CER = (S + I + D) / N × 100（S/I/D 为替换/插入/删除数，N 为参考文本字符总数）；WER 同理以词为单位。

## 6. 主要结论与发现

- **最优模型**：CNN-BGRU-CTC 表现最佳，在测试集上 CER 5.2%、WER 16.9%（验证集 CER 5.2%、WER 17.2%），且计算开销低于 CNN-BLSTM-CTC，被命名为 "UKHR model"。
- **双向优于单向**：BLSTM/BGRU 变体一致优于对应的单向 LSTM/GRU，说明图像序列识别中利用双向上下文更有利。
- **超参数结论**：学习率 0.0002、RMSprop、批大小 32 为 BGRU 模型最优组合；架构上 CNN-BGRU-CTC(2)（7 Conv + 3 BGRU）在性能、复杂度与泛化间取得最佳平衡，更深架构收益甚微且训练更慢。
- **调度器有效**：指数衰减调度（e^-0.2，第25轮后）将测试 CER 从 5.7% 降至 5.2%、WER 从 18.4% 降至 16.9%，且训练轮次更少（70→59）。
- **定性发现**：模型能正确识别常用乌尔都语/阿拉伯语变音符号（zer、zabar、pesh、shadda、takhallus 符号、诗句符号 ؎ 等）及标点，而 Google Cloud Vision API 无法识别这些变音符号——这是本文模型相对商用 API 的显著优势。
- **失败模式**：错误主要来自字符严重重叠、形近字符混淆（如 د/و、سی/ی、ڑا/اٹا）、低质量/模糊图像，以及空格插入/删除错误。
